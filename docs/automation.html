Automation

arc embeds a small local automation bridge: a localhost-only TCP server that exposes the same command surface the user interface drives, so external tools, scripts, agents, editors, can inspect and edit the document model while every change behaves as if it had been made by hand in the app.

The bridge

When arc starts, it binds a TCP server on 127.0.0.1 (first port from 3987, trying up to six addresses if yours is busy) and dispatches requests onto the same internal command layer behind the Tauri webview IPC. Concretely that means every mutation:

  • records a proper undo/redo entry, just like a click in the UI would,
  • fires the Lua plugin lifecycle hooks (new, open, save…),
  • emits the same scene/document events so an open editor window refreshes live.

Documents are plain JSON: the payloads the bridge accepts are the same shapes stored in .arc files, e.g. {"type":"box","width":10,"height":2,"depth":5} or {"type":"cylinder","radius":3,"height":8,"segments":12} (the shape tags are snake case: box, cylinder, line_curve, polyline_curve, circle_curve, rectangle_curve, …).

bridge.json and auth

The running app writes connection info next to its other settings. Each client connect must authenticate with the token from that file before accepting commands.

Connection info
ItemValue
Filebridge.json in the app data dir: Linux ~/.local/share/com.arc.cad/, macOS ~/Library/Application Support/com.arc.cad/, Windows %APPDATA%\com.arc.cad\
Contents{"port":3987,"token":"…"}
Port sourceenv ARC_BRIDGE_PORT, else 3987 (auto-increment up to 3987+5 when busy)
File overrideenv ARC_BRIDGE_INFO: path the file is written to
Authper connection, first line {"auth":"<token>"}, server answers {"ok":true} and closes the connection if it fails

arc must be running when a bridge client starts; restarting the app regenerates the token and port, so long-lived clients simply re-read bridge.json and reconnect (the bundled MCP client does this on every start).

Protocol

One TCP connection per session. After auth it exchanges HTTP-free, newline-delimited JSON:

// client → server, one line per call
{"id":"1","cmd":"get_state","params":{}}
{"id":"2","cmd":"create_entity","params":{"document_id":"doc-1","geometry":{"type":"box","width":10,"height":2,"depth":5}}}
{"id":"3","cmd":"set_transform","params":{"document_id":"doc-1","updates":[{"id":"ent-…","transform":{"position":[0,0,0],"rotation":[0,0,0,1],"scale":[1,1,1]}}]}}

// server → client, one line per response
{"id":"1","ok":true,"result":{…AppOverview…}}
{"id":"2","ok":true,"result":{"id":"ent-…","name":"Box 1"}}
{"id":"3","ok":false,"error":"unknown document doc-9"}

Streaming is not multiplexed: each connection processes lines sequentially and answers in order, so client code can keep a socket open and post a call per line.

Commands

The bridge accepts the same commands as the editor IPC (see the sources in src-tauri/src/bridge.rs and commands.rs for exact signatures):

Command groups
GroupCommands
Stateget_state, get_settings, get_plugins
Settingsset_settings
Documentsnew_document, open_document, save_document, close_document, set_active_document, get_scene
Entitiescreate_entity, update_geometry, delete_entities, duplicate_entities, explode_entities, set_transform, set_entity_props, set_selection, raycast
Historyundo, redo
Layersadd_layer, delete_layer, rename_layer, set_layer_visible, set_layer_locked, set_layer_color, set_active_layer
Pluginsreload_plugins, set_plugin_enabled
Exportexport_scene (OBJ / binary STL)

A minimal useful loop: get_state to see documents, then get_scene for entities/layers, then create_entity + set_transform to place geometry. list_projects(data_dir) also exists on the Tauri IPC (the startup screen uses it to list .arc files in a folder).

MCP client

crates/arc-mcp is a Model Context Protocol stdio server that drives the bridge on the assistant's behalf, so any MCP-capable client (opencode, Claude Desktop, …) can edit the open model. Build it next to the app: cargo build -p arc-mcp.

It ships essentially one tool per bridge command:

arc_get_state · arc_get_scene · arc_get_settings · arc_get_plugins
arc_new_document · arc_open_document · arc_save_document
arc_close_document · arc_set_active_document
arc_create_entity · arc_update_geometry · arc_delete_entities
arc_duplicate_entities · arc_explode_entities · arc_set_transform
arc_set_position · arc_set_entity_props · arc_raycast
arc_undo · arc_redo
arc_add_layer · arc_delete_layer · arc_rename_layer · arc_set_settings
arc_set_active_layer · arc_set_layer_visible · arc_set_layer_locked · arc_set_layer_color
arc_set_plugin_enabled · arc_set_selection · arc_reload_plugins · arc_export_scene

// resources: arc://doc/<document_id>: a snapshot of one document's scene

arc_set_position is the convenience wrapper: it takes an entity id and a position and sends an identity-rotation/scale transform. Quaternions still pass through arc_set_transform when rotation matters. Omit the document id to act on the active document.

Wiring it into an MCP client is a single process entry:

// e.g. Claude Desktop, generic MCP stdio config
{
  "mcpServers": {
    "arc": { "command": "/home/<you>/…/arc/target/debug/arc-mcp" }
  }
}

The client keeps no state: each process start it reads bridge.json, opens one connection for the request, authenticates and returns the result, so app restarts only require relaunching the client process.

Raw socket example

The protocol is deliberately tiny; if MCP is overkill, a script can talk to it directly. Below is a compact Python example that checks the running app and drops a box at the origin of the active document: 

import json, socket, pathlib

info = json.loads(pathlib.Path("~/.local/share/com.arc.cad/bridge.json").expanduser().read_text())
sock = socket.create_connection(("127.0.0.1", info["port"]))
f = sock.makefile("rw", encoding="utf-8", newline="\n")

f.write(json.dumps({"auth": info["token"]}) + "\n"); f.flush()
print(json.loads(f.readline()))          # {"ok": true}

def call(n, cmd, **params):
    f.write(json.dumps({"id": n, "cmd": cmd, "params": params}) + "\n"); f.flush()
    return json.loads(f.readline())

print(call(1, "get_state")["result"])
print(call(2, "create_entity", document_id="doc-1",
           geometry={"type": "box", "width": 10, "height": 2, "depth": 5}))
